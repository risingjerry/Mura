# Agent guide — Mura

Mura v2 is a single Swift command-line tool, `mura`, that renders a day's to-do list into an Excalidraw-style hand-drawn PNG and sets it as the macOS wallpaper on every display. To *use* Mura from an agent, read `skills/mura/SKILL.md`; this file is for working on the repo.

## Product intent

Agent-native, light, nothing resident. An agent writes the plan; Mura handles layout, drawing and the daily switch. No editor or drawing panel. A LaunchAgent runs `mura tick` every 5 minutes (a few milliseconds when nothing changed); there is no daemon.

## Layout

- `Sources/MuraCore/Day.swift` — the day model and its Markdown format.
- `Dates.swift` — date words, timezone-aware "today", date labels.
- `Home.swift` — the data directory (`~/Library/Application Support/Mura`, or `MURA_HOME`), config, apply history, file lock.
- `Renderer.swift` — layout (font fitting, two columns, overflow) and drawing with CoreText + CoreGraphics.
- `Rough.swift` + `RoughJS.swift` — rough.js running in JavaScriptCore (generator only, no DOM) for the sketchy shapes. `RoughJS.swift` is generated by `script/vendor_rough.sh`; do not edit it.
- `Fonts.swift` — Virgil + Xiaolai, downloaded by `mura setup` with pinned SHA-256; system fonts as fallback.
- `Desktop.swift` — the only code that touches the real desktop: NSWorkspace for the current Space, plus the all-Spaces edit of the private wallpaper store (backed up, verified, rolled back if macOS rejects it).
- `Schedule.swift` — the LaunchAgent. `Mura.swift` — commands and the JSON envelope. `Sources/mura/main.swift` — entry point.

## Build, test, run

```sh
swift test                                         # unit tests; they use a fake Desktop and never touch the wallpaper
swift build -c release --product mura
MURA_HOME=/tmp/mura-dev .build/release/mura render --date tomorrow --size 1920x1200 --out /tmp/mura-dev/out
script/install.sh                                  # real install for the current user
```

Use `MURA_HOME` for any experiment so the user's real days and history stay untouched. `render` never changes the wallpaper; `apply`, `undo`, `tick` and editing today do.

## Rules

- Keep the output contract: one JSON object `{ok, command, data | error{code,message}, warnings?}`, exit 0/1/2. Add commands to `Mura.help` and `skills/mura/SKILL.md`.
- Bump `Renderer.version` when the drawing changes, so cached renders are redrawn.
- The wallpaper store (`~/Library/Application Support/com.apple.wallpaper/Store/Index.plist`) is undocumented. Any change there must keep entries complete (`individual` = `Desktop` + `Idle`; `linked` = `Linked`), take a backup first, and verify afterwards; macOS resets the whole store when it cannot decode one entry.
- Visual checks: render previews and look at them before claiming a layout change works.
- No personal data in the repo (names, local paths, real to-do contents). Fonts are not committed.
